## SSH : Konsep Private Public Key

### ***Private Key***

**Private Key** bertindak sebagai verificator.

### ***Public Key***

**Public Key** bertindak sebagai shared key.

### ***Authorized Key File***

**authorized_key file** bertindak sebagai registri / tempat penyimpanan public file yang dikenali.

```
"Saya akan menerima autentikasi seseorang yang bisa membuktikan / memiliki private key yang sesuai dengan public key yang terdaftar disini"
```

Jadi, private key sebagai bukti kepemilikan dari public key. 

Hal tersebut membuat pada host client membutuhkan 2 key (private dan public) sedangkan pada host server bisa hanya memiliki public key registri (authorized key file). Selain itu, menjadikan host yang hanya memiliki public key tidak akan bisa terkoneksi ke host server jika tidak juga memiliki private keynya.
